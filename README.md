# FlyAI — אפליקציית שיפוט להקאתון

אפליקציית ווב לנייד (PWA) לשיפוט 65 רעיונות ההקאתון, שקלול הציונים והצגת התוצאות.
בעברית, RTL, מותאמת לטלפון, ועובדת גם בלי רשת.

---

## מה יש כאן

**ארבעה מסכים:**

| מסך | מה הוא עושה |
|---|---|
| **שיפוט** | רשימת הרעיונות עם חיפוש, סינון (לשיפוט / הושלמו / מסומנים) ומד התקדמות. לחיצה פותחת כרטיס שיפוט. |
| **תוצאות** | דירוג משוקלל, כיול שופטים, וטבלה מלאה. ייצוא CSV. |
| **מעפילים** | הרעיונות שעלו לשלב ב׳. |
| **הגדרות** | משקלות, שיטת שקלול, חיבור לענן, גיבוי, ערכת צבעים. |

**כרטיס השיפוט** מציג את חמשת המדדים עם כפתורי מגע גדולים, תיאור מילולי לכל ציון,
שדה הערות, כוכב לסימון מועמד מוביל, וכפתור "לא ראיינתי" למי שלא נכח בראיון.
הציון המשוקלל מתעדכן בזמן אמת בראש הכרטיס. כל שינוי נשמר מיד — אין כפתור "שמור".

## המדדים והשקלול

| מדד | סוג | משקל ברירת מחדל |
|---|---|---|
| בגרות — היכולת להגיע ל-MVP מהיר | 1–5 | 25% |
| הרצה על תשתיות קיימות במוצרים | 1–5 | 20% |
| ערך מבצעי ועסקי | 1–5 | 25% |
| Scalability | 1–5 | 20% |
| צוות הטרוגני (כלי טיס + מל"ט) | בינארי | 10% |

**כל המשקלות ניתנות לכוונון** במסך ההגדרות, כולל המדד הבינארי. המשקלות יחסיים —
האחוזים מחושבים מהסכום, כך שאפשר להזיז מחוון אחד בלי לתקן את השאר. משקל 0 מוציא
מדד מהחישוב לגמרי.

**החישוב:** כל מדד מנורמל ל-0..1 (ציון 1→0, ציון 5→1; בינארי→0 או 1), מוכפל
במשקלו, והתוצאה היא ממוצע משוקלל על סולם 0–100. כרטיס שמולא חלקית מחשב מחדש את
המשקלות על המדדים שכן מולאו, כך שלא נוצר אפס מלאכותי.

**ציון הרעיון** הוא הממוצע על פני השופטים שדירגו אותו. שופט שסימן "לא מדרג" לא
נספר כלל.

### נרמול לפי שופט

מתג בהגדרות (כבוי כברירת מחדל). כשהוא דלוק, הציונים של כל שופט ממורכזים מחדש
לממוצע ולפיזור של הפאנל.

**מתי להדליק:** אם מחלקים את הראיונות בין השופטים ולא כולם רואים את כולם. בלי
נרמול, רעיון שראיין אותו שופט מחמיר נענש על מי שראיין אותו במקום על איכותו.

**מתי להשאיר כבוי:** אם כל השופטים מדרגים את כל הרעיונות — אז הממוצע הפשוט כבר
הוגן, והנרמול רק מוסיף רעש.

לשונית **"כיול שופטים"** בדשבורד מראה את הסטייה של כל שופט מממוצע הפאנל, כך
שאפשר להחליט על בסיס נתונים ולא על תחושה. הנרמול מופעל רק על שופט עם 3 כרטיסים
לפחות; מתחת לזה אין מספיק מידע כדי להעריך את ההטיה שלו, ורק ההיסט מנוטרל.

### מחלוקות

רעיון שהפער בין השופטים בו גדול מ-25 נקודות מסומן ב"פער גדול"; מעל 15 — "פער
בינוני". הסימון הוא רמז לדיון, לא עונש — הוא לא משפיע על הציון.

## הרצה

```bash
npm install
npm run dev                    # שרת פיתוח (ללא שער), כולל כתובת רשת לנייד
npm run seal -- "<קוד>"        # הצפנת רשימת הרעיונות בקוד הגישה
npm run build:gated            # הבנייה שעולה לאוויר — עם שער והצפנה
npm run build                  # בנייה ללא שער (לבדיקות מקומיות)
npm run preview                # תצוגה מקדימה של הבנייה
npm test                       # בדיקות מנוע השקלול
npm run icons                  # יצירה מחדש של אייקוני ה-PWA
```

`npm run dev` מדפיס גם כתובת **Network** (למשל `http://172.20.10.7:5173/`).
כל טלפון באותה רשת יכול לפתוח אותה — נוח לבדיקה מהירה לפני שמעלים לענן.

### התקנה כאפליקציה בנייד

פותחים את הכתובת בדפדפן ובוחרים "הוסף למסך הבית". האפליקציה נפתחת במסך מלא, בלי
סרגל כתובות, ועובדת גם בלי רשת.

> **חשוב — HTTPS.** התקנה כאפליקציה ועבודה אופליין דורשות *secure context*:
> `https://` או `localhost`. כתובת IP על `http://` (כמו כתובת ה-Network של שרת
> הפיתוח) **אינה** secure context, ולכן ה-service worker לא נרשם שם ואין
> "הוסף למסך הבית" מלא. השיפוט עצמו עובד שם רגיל — הכל נשמר ב-localStorage.
>
> ליום ההקאתון: להעלות את `dist/` לאירוח עם HTTPS (Vercel/Netlify/שרת פנימי עם
> תעודה). אז גם ההתקנה וגם האופליין עובדים.
>
> הערה טכנית: מסיבה זו האפליקציה לא מסתמכת על `crypto.randomUUID` (קיים רק
> ב-secure context) אלא על `crypto.getRandomValues` — ראו `src/lib/ids.ts`.

## חיבור לענן (Supabase)

בלי חיבור, האפליקציה עובדת מקומית לגמרי — כל שופט על המכשיר שלו. כדי שכולם יראו
דשבורד משותף:

1. פותחים פרויקט חדש ב-[supabase.com](https://supabase.com).
2. ב-SQL Editor מריצים את `supabase/schema.sql` — הוא יוצר את הטבלאות, ההרשאות,
   העדכונים החיים, ומזין את 65 הרעיונות.
3. ב-Project Settings → API מעתיקים את ה-**Project URL** ואת ה-**anon key**.
4. מדביקים אותם במסך ההגדרות → "סנכרון בענן" → "התחבר".
5. השופטים האחרים מדביקים את אותם שני ערכים אצלם.

לחלופין, לבנייה מוגדרת מראש: יוצרים `.env` (ראו `.env.example`) והכתובות ייטענו
אוטומטית בלי שאף אחד יצטרך להדביק כלום.

### אבטחה — לקרוא לפני שמחברים

האפליקציה מתחברת עם ה-**anon key** בלבד. כל השופטים חולקים זהות אחת, והאפליקציה
מבדילה ביניהם לפי מזהה השופט שהיא שולחת. המשמעות: **כל מי שמחזיק את הצמד
URL + anon key יכול לקרוא ולכתוב את כל התוצאות.** התייחסו אליו כסיסמה משותפת של
הפאנל, ואל תפרסמו אותו.

בהתאם לכך — שקלו מה נכנס לענן ציבורי. שמות הרעיונות והמובילים הם מידע ארגוני;
אם זו בעיה, אפשר להשאיר את האפליקציה במצב מקומי ולאחד ידנית (ראו למטה), או
להריץ Supabase self-hosted ברשת הפנימית.

### מצב אופליין

כל שמירה נכנסת קודם ל-localStorage ונכנסת לתור לענן. שופט בחדר בלי קליטה ממשיך
לעבוד רגיל, והתור מתרוקן כשהחיבור חוזר. במיזוג — הכרטיס העדכני יותר מנצח, ושום
ציון לא נמחק.

## איחוד ידני בלי ענן

אם עובדים מקומית: כל שופט לוחץ **ייצוא** בהגדרות ושולח את קובץ ה-JSON. מי שמרכז
טוען את הקבצים דרך **טעינת קובץ שופט**, והדשבורד מציג את התמונה המלאה. אפשר
לטעון כמה קבצים ברצף — האיחוד מצטבר.

## קוד גישה והצפנה

האתר ציבורי, ולכן רשימת הרעיונות **לא נשלחת אליו כטקסט**. `ideas.json` מוצפן
(AES-256-GCM, מפתח נגזר מהקוד ב-PBKDF2 עם 250,000 סבבים) לתוך
`public/ideas.sealed.json`, וזה הקובץ היחיד שעולה לאוויר. מי שנכנס בלי הקוד רואה
מסך קוד — ומי שיפתח View Source ימצא רק ציפר.

```bash
npm run seal -- "הקוד-שלך"    # יוצר מחדש את public/ideas.sealed.json
npm run build:gated            # בנייה עם השער
```

**חשוב:** הקובץ שנמצא כרגע ב-repo נאטם עם קוד זמני לצורך בדיקה. הרץ `npm run seal`
עם הקוד האמיתי שלך לפני ההעלאה, ומסור אותו לשופטים בערוץ נפרד מהקישור.

להחלפת הקוד: `npm run seal` מחדש ו-push. השופטים יתבקשו להזין את הקוד החדש
(ה-service worker לא מטמין את הקובץ הזה בדיוק בשביל זה).

`ideas.json` עצמו **מוחרג מ-git** — ראה `.gitignore`. GitHub Pages בחשבון חינמי
דורש repo ציבורי, וקובץ שמופיע ב-repo קריא לכולם; אילו היינו מעלים אותו,
ההצפנה הייתה חסרת משמעות. שמור עותק מקומי.

`scripts/check-bundle.mjs` רץ בכל בנייה ונכשל אם כותרת רעיון או שם מוביל הופיעו
באיזשהו קובץ ב-`dist/`. זו הבדיקה שמוכיחה שההפרדה באמת עובדת ולא רק אמורה לעבוד.

## העלאה ל-GitHub Pages

הקוד כבר מוכן — יש workflow שבונה ומעלה בכל push ל-`main`.

> הפקודות למטה כתובות ל-PowerShell (ברירת המחדל ב-Windows). **שורה אחת בכל
> פעם** — Windows PowerShell 5.1 לא תומך ב-`&&` לשרשור פקודות, וינפיק
> `The token '&&' is not a valid statement separator in this version`.

```powershell
# 1. אטום את הרעיונות עם הקוד האמיתי
npm run seal -- "הקוד-שלך"
git add -A
git commit -m "seal ideas"

# 2. צור repo בשם FlyAI ב-github.com (ציבורי) והתחבר אליו
git remote add origin https://github.com/<המשתמש-שלך>/FlyAI.git
git push -u origin main
```

3. ב-GitHub: **Settings → Pages → Source: GitHub Actions**.
4. ה-workflow ירוץ, והאתר יעלה ל-`https://<המשתמש-שלך>.github.io/FlyAI/`.

אם תקרא ל-repo בשם אחר — לא צריך לשנות כלום, ה-workflow לוקח את שם ה-repo
אוטומטית ל-`base`.

**Supabase (אופציונלי):** ב-Settings → Secrets and variables → Actions הוסף
`VITE_SUPABASE_URL` ו-`VITE_SUPABASE_ANON_KEY`, והם ייצרבו לבנייה כך שאף שופט
לא יצטרך להדביק כלום. בלעדיהם האפליקציה עולה במצב מקומי וכל אחד יכול לחבר ידנית.

הקישור נושא HTTPS, ולכן שם גם ההתקנה כאפליקציה וגם העבודה אופליין עובדות.

## עיצוב ומיתוג

הזהות נגזרה מה-key visual של ההקאתון (`FLY.png`): שמי לילה כהים, גרדיאנט
כחול→סגול על ה-"AI", מסגרות HUD, ופס זריחה חם בתחתית. כהה הוא ברירת המחדל;
בהיר הוא בחירה מפורשת בהגדרות.

**כל המיתוג יושב ב-`src/brand.css`.** זהו הקובץ היחיד שמכיל צבעים — `styles.css`
משתמש רק בתפקידים סמנטיים (`--accent`, `--surface-1`, `--text-primary`…). לשינוי
מיתוג עתידי: ערוך את הטוקנים שם, ואל תיגע בשום מקום אחר.

צבעי הגרפים אומתו מול משטח הכרטיס הכהה (`#0c1730`) — טווח בהירות, רוויה,
הפרדה לעיוורי צבעים בכל הזוגות, וניגודיות ≥3:1. אם משנים אותם, יש להריץ את
הוולידציה מחדש.

## שני השלבים

**שלב א׳ — ראיונות (65 רעיונות).** כל השופטים מדרגים. בסיום, בדשבורד, כפתור
**"קבע 10 מעפילים"** מקבע את העשירייה המובילה. מספר המעפילים ניתן לשינוי
בהגדרות.

**שלב ב׳ — הקאתון.** מחליפים ל"שלב פעיל: ב׳" בהגדרות. הרשימה מצטמצמת לרעיונות
שעלו, והשיפוט מתחיל מחדש — ציוני שלב א׳ נשמרים בנפרד ולא מתערבבים. אפשר לשנות
משקלות בין השלבים (למשל להוריד את משקל "בגרות" ולהעלות "ערך מבצעי" אחרי שכולם
כבר הוכיחו MVP).

## הערה על משקלות משותפים

המשקלות, מספר המעפילים והשלב הפעיל הם **הגדרות של הפאנל, לא של השופט**. כששופט
משנה אותם והוא מחובר לענן, זה משתנה אצל כולם מיד. זה מכוון — הדירוג חייב להיות
מחושב באותו אופן לכולם — אבל כדאי לסכם מראש מי קובע אותם.
